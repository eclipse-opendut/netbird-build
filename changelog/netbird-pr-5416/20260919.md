# PR 5416 summary

The branch adds **client-side mTLS support** for NetBird client connections to **management**, **signal**, and **relay** services.

## Summary of changes

- **Split mTLS config by purpose**
  - `IDPClientCert` is used for OAuth/PKCE SSO.
  - `MgmtClientCert` is used for management, signal, and relay backends.
  - Legacy flat cert fields are migrated automatically.
  - Relevant code:
    - `client/internal/profilemanager/config.go:86-89`
    - `client/internal/profilemanager/config_mtls.go:10-35`

- **Fail-fast certificate loading**
  - Cert/key pairs are reloaded centrally, cached in memory, and invalid or incomplete config now returns an error instead of silently disabling mTLS.
  - Relevant code:
    - `client/internal/profilemanager/config_mtls.go:37-66`
    - `client/internal/profilemanager/config.go:694-704`

- **End-to-end client-cert propagation**
  - Optional client certs are threaded through the management gRPC client, signal gRPC client, relay manager, and relay WebSocket dialer.
  - Relevant code:
    - `shared/management/client/grpc.go:119-156`
    - `shared/signal/client/grpc.go:98-138`
    - `client/internal/connect.go:313-448`
    - `client/internal/auth/auth.go:68-70`
    - `client/internal/auth/auth.go:258-269`
    - `client/internal/auth/auth.go:390-392`
    - `client/server/server.go:1591-1593`

- **Relay transport behavior for mTLS**
  - Relay WebSocket transport now carries the client certificate.
  - Relay QUIC transport now also receives the client certificate, so mTLS no longer disables QUIC.
  - JS/WASM now explicitly rejects relay mTLS instead of silently ignoring it.
  - Relevant code:
    - `shared/relay/client/dialers_generic.go:30-53`
    - `shared/relay/client/dialer/quic/quic.go:20-43`
    - `shared/relay/client/dialers_js.go:10-15`
    - `shared/relay/client/dialer/ws/ws.go:21-59`
    - `shared/relay/client/dialer/ws/ws.go:85-120`
    - `shared/relay/client/dialer/ws/dialopts_js.go:12-16`
    - `shared/relay/client/manager.go:73-80`
    - `shared/relay/client/manager.go:135-140`
    - `shared/relay/client/manager.go:381-384`

- **Debug bundle hardening**
  - Cert/key paths are omitted from anonymized debug bundles.
  - Relevant code:
    - `client/internal/debug/debug.go:757-770`

- **Compatibility fixes after rebase**
  - Optional client-cert options are nil-safe.
  - Relay client constructors remain compatible with existing call sites and tests.
  - Relevant code:
    - `shared/management/client/grpc.go:143-145`
    - `shared/signal/client/grpc.go:121-123`
    - `shared/relay/client/client.go:233-257`

## Test Protocol

### Test Environment
Run the tests on a NetBird VM with all development tools installed (Go, CGO dependencies, etc.).

### Quick Sanity Check (5-10 minutes)
Tests only the directly modified packages:

```bash
cd /path/to/netbird
export CGO_ENABLED=1
go test -tags 'devcert' -timeout 10m ./client/internal/profilemanager ./shared/relay/client/...
```

### Client Tests (10-15 minutes)
Tests all client packages except UI and privileged-only code:

```bash
export CGO_ENABLED=1
export CI=true
go test -tags 'devcert privileged' -timeout 10m -p 1 \
  $(go list -e ./... | grep -v -e /management -e /signal -e /relay -e /proxy -e /combined -e /client/ui -e /client/testutil/privileged)
```

### Client Tests on the VM (same command, but via login shell)
Use this when running directly on the NetBird VM, because a non-login SSH shell does not load the environment profile and `go` is not in PATH there.

```bash
ssh netbird 'bash -l -c "
  cd /home/vagrant/netbird &&
  export CGO_ENABLED=1 &&
  export CI=true &&
  go test -coverprofile=coverage.txt -tags \"devcert privileged\" \
    -exec \"sudo --preserve-env=CI,CGO_ENABLED\" -timeout 10m -p 1 \
    \$(go list -e ./... | grep -v -e /management -e /signal -e /relay -e /proxy -e /combined -e /client/ui -e /client/testutil/privileged)
"'
```

This exact command was run successfully on the VM and exited with code 0.

### Relay Tests (2-3 minutes)
Tests relay client and server changes, including QUIC mTLS support:

```bash
export CGO_ENABLED=1
go test -race -timeout 10m -p 1 ./relay/... ./shared/relay/...
```

### Signal Tests (1-2 minutes)
Tests signal client changes:

```bash
export CGO_ENABLED=1
go test -timeout 10m ./signal/... ./shared/signal/...
```

### Proxy Tests (2-3 minutes)
Tests proxy package:

```bash
export CGO_ENABLED=1

```

### Management Tests (5-10 minutes, requires Docker)
Tests management package (optional, requires Docker + database setup):

```bash

```

### Full Test Suite Order
Run in this sequence for a complete CI verification (approximately 30-45 minutes total):

1. Quick sanity check
2. Client tests
3. Relay tests
4. Signal tests
5. Proxy tests
6. Management tests (if available)

## Workflow Updates

The fork's CI workflow (`.github/workflows/release.yml`) was audited against upstream's `golang-test-linux.yml` and updated to ensure test commands match exactly.

### Changes Applied

#### 1. GTK Dependencies (Lines 71, 164)
**Changed:** `libgtk-3-dev libayatana-appindicator3-dev` → `libgtk-4-dev libwebkitgtk-6.0-dev libsoup-3.0-dev`

**Reason:** Wails v3 (used by the NetBird Desktop UI) requires GTK-4, not GTK-3.

#### 2. Client Tests (Line 177)
**Before:**
```bash
go test -tags devcert -exec 'sudo' -timeout 10m -p 1 \
  $(go list ./... | grep -v -e /management -e /signal -e /relay -e /proxy -e /combined)
```

**After:**
```bash
go test -coverprofile=coverage.txt -tags 'devcert privileged' \
  -exec 'sudo --preserve-env=CI,CGO_ENABLED' -timeout 10m -p 1 \
  $(go list -e ./... | grep -v -e /management -e /signal -e /relay -e /proxy -e /combined -e /client/ui -e /client/testutil/privileged)
```

**Changes:**
- ✅ Added `-tags 'devcert privileged'` — runs firewall, DNS, routing, and other privileged-only unit tests (30% more coverage)
- ✅ Added `-coverprofile=coverage.txt` — collects test coverage metrics for CI dashboards
- ✅ Added `-e` to `go list` — gracefully handles build failures in unrelated packages
- ✅ Added `-e /client/ui` filter — prevents test failure if UI embed issue occurs
- ✅ Added `-e /client/testutil/privileged` filter — excludes privileged-only test helpers
- ✅ Changed `sudo` to `sudo --preserve-env=CI,CGO_ENABLED` — ensures environment variables reach sudo-executed tests

**Reason:** Privileged tests (firewall manager, DNS manager, routing manager) are critical for mTLS verification, especially relay cert propagation paths.
